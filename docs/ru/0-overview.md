# Библиотека siesta: Обзор и быстрый старт

Библиотека `siesta` — декларативная библиотека для создания терминальных интерфейсов (TUI) на языке Yukino. Вместо ручного процедурного позиционирования элементов, вычисления координат и посимвольного вывода escape-последовательностей, `siesta` позволяет описывать структуру интерфейса в декларативных файлах спецификаций `.spes`.

Во время сборки процедурный макрос компилирует эту разметку напрямую в строго типизированные классы Yukino, обеспечивая максимальное быстродействие, нулевые накладные расходы рантайм-парсинга и строгую типобезопасность.

---

## 1. Введение в TUI для начинающих

Интерфейс пользователя в терминале (Text/Terminal User Interface, TUI) представляет собой интерактивную визуальную среду, работающую внутри символьной сетки консоли.

### 1.1 Как терминал работает на низком уровне
Обычная консольная программа (CLI) работает в **потоковом режиме**: вызов `println` последовательно отправляет строки текста в стандартный вывод `stdout`, а терминал прокручивает экран вниз по мере поступления новых строк. В таком режиме программа не знает, где на экране находится курсор, и не может вернуть курсор на 5 строк выше, чтобы обновить отдельное число.

TUI-приложение работает принципиально иначе — в **режиме двумерной координатной сетки**:
1. Терминал рассматривается как прямоугольная матрица знакомест фиксированного размера (например, 120 столбцов на 30 строк). Каждая ячейка сетки имеет координаты `(x, y)` и хранит символ, цвет текста, цвет фона и визуальные атрибуты (жирный, тусклый, подчеркнутый).
2. Программа переводит терминал в **сырой режим (raw mode)** через системные средства `std.itermtool`. В сыром режиме:
   - Отключается построчная буферизация операционной системы: каждое нажатие клавиши мгновенно передается в программу (не нужно ждать нажатия `Enter`).
   - Отключается автоматическое эхо ввода (нажатые клавиши не печатаются хаотично посреди нарисованных окон).
   - Включается **альтернативный буфер экрана (alternate screen buffer)**: терминал сохраняет текущую командную строку пользователя, открывает чистый виртуальный экран для TUI-приложения, а при завершении программы мгновенно возвращает пользователя в исходную командную строку без мусора на экране.

### 1.2 Проблема ручной отрисовки (мерцание и производительность)
Если писать TUI вручную, типичная ошибка начинающего разработчика выглядит так:
```
Каждый кадр (например, 30 раз в секунду):
1. Отправить команду очистки экрана: \x1b[2J
2. Заново нарисовать все рамки, текст и кнопки через println
```
При таком подходе экран неизбежно **мерцает (flickering)**: человеческий глаз успевает заметить момент между очисткой экрана и выводом нового кадра. Кроме того, отправка десятков тысяч байт ANSI-команд в терминал каждый кадр создает паразитный нагрев процессора и дергает видеоподсистему консоли.

### 1.3 Как эту проблему решает siesta: Двойная буферизация
В библиотеке `siesta` используется промышленный алгоритм **двойной буферизации (`DoubleBuffer`)** с дифференциальным сбросом:
- В оперативной памяти поддерживаются два буфера ячеек одинакового размера:
  - `front_buffer` (передний буфер) — точная копия того, что в данный момент видит пользователь на экране.
  - `back_buffer` (задний буфер) — закадровый холст, на котором программа и виджеты рисуют новый кадр.
- При вызове рендера функция дифференцирования сравнивает строки `back_buffer` со строками `front_buffer`.
- Терминалу передаются только те ячейки, которые **реально изменились** с прошлого кадра (dirty lines). Неизменившиеся участки (статичные рамки, неизменные заголовки, фон) вообще не трогаются.
- Между соседними ячейками одного цвета оптимизатор объединяет ANSI-последовательности, сокращая сетевой и терминальный трафик в разы.
- Результат: идеально плавный рендеринг без единого мерцания на любой частоте обновления.

## 2. Почему декларативный синтаксис SPES

Если создавать TUI-интерфейс процедурным кодом на чистом языке программирования, разработчик сталкивается с лавинообразным ростом шаблонного кода:
- Для каждой панели нужно вручную вычислять абсолютные координаты: `x = 2`, `y = 10`, `w = (term_w - 4) / 2`.
- При изменении размера окна терминала пользователем все эти координаты нужно вручную пересчитывать, не допуская отрицательных значений или выхода за границы.
- Код бизнес-логики (обработка нажатий, сетевые запросы) оказывается перемешан с процедурным кодом рисования рамок и линий.

Синтаксис **SPES (`.spes`)** отделяет архитектуру интерфейса от вычислений:
1. Вы описываете структуру экрана в виде чистого и понятного дерева контейнеров и виджетов (`col`, `row`, `block`, `button`, `table`).
2. Задаете правила адаптивности: `fill: true` (занять оставшееся пространство), `minWidth: 80` (скрыть колонку, если окно уже 80 ячеек), `breakpoint: "desktop"`.
3. **Нулевой оверхед в рантайме**: в отличие от веба или Electron, `.spes` не парсится при запуске программы. Процедурный макрос `#[siesta::res]` читает файл во время сборки и компилирует его в чистый код на Yukino. Программа выполняется с нативной скоростью скомпилированного бинарника.

## 3. Архитектура и принцип работы

Архитектура системы состоит из трех уровней:

```
+----------------------------------------------------------------+
|                     1. Файл разметки (.spes)                  |
|   theme / screen / component / dialog / shortcuts / widgets    |
+----------------------------------------------------------------+
                               |
                               v (процедурный макрос siesta::res во время сборки)
+----------------------------------------------------------------+
|                2. Сгенерированные классы Yukino                |
|   public class MainScreen extends Screen {                     |
|       public counter: int32                                    |
|       public fun build_layout(ref ctx: LayoutContext)          |
|       public fun draw(ref buf: TerminalBuffer)                 |
|       public fun handle_key(key: KeyEvent) -> bool             |
|   }                                                            |
+----------------------------------------------------------------+
                               |
                               v (компиляция yukinc + связь с siesta_core)
+----------------------------------------------------------------+
|                   3. Рантайм-ядро siesta_core                  |
|   SiestaApp / DoubleBuffer / DiffSpans / LayoutEngine / Focus  |
+----------------------------------------------------------------+
```

### 3.1 Как данные и события перемещаются между Yukino и SPES

1. **Из SPES в Yukino**:
   - Макрос создает нативный класс экрана `public class <Name> extends Screen` или диалога `extends Dialog`.
   - Контейнеры `col` и `row` преобразуются в метод `build_layout(ref ctx)`, рассчитывающий точные прямоугольники `Rect` для каждого дочернего виджета с учетом flex-весов.
   - Дерево виджетов преобразуется в метод `draw(ref buf: TerminalBuffer)`, который послойно отрисовывает элементы в буфер ячеек.
   - Горячие клавиши из блока `shortcuts` преобразуются в метод `handle_key(key: KeyEvent) -> bool`.

2. **Из Yukino в SPES**:
   - Переменные из блока `state` становятся публичными полями сгенерированного класса.
   - В коде программы вы просто изменяете поле: `screen.counter = screen.counter + 1`.
   - При следующем вызове `app.render_frame()` метод `draw()` считает обновленное значение поля и мгновенно выведет его в буфер.
   - Свойство `bind: fieldName` связывает поля ввода (`input`, `textarea`, `checkbox`) с состоянием экрана без необходимости писать ручные обработчики `on_change`.

## 4. Подключение библиотеки к проекту

Добавьте зависимость в секцию `[libs.runtime]` манифеста `yuki.toml`:

```toml
[libs.runtime]
siesta = { git = "https://github.com/shareui/siesta", tag = "0.1.0", package = "siesta" }
```

### Импорт модулей в исходном коде
Библиотека экспортирует готовые типы через корневой модуль `siesta`:

```yukino
load siesta: Cell, TerminalBuffer, DoubleBuffer, LayoutContext, Screen, Dialog, SiestaApp, detect_is_dark_mode
load siesta: Rect, init_rect, rect_inner, rect_intersect, LayoutNode, init_layout_node, layout_row, layout_col
load siesta: Constraint, init_constraint_length, init_constraint_percent, init_constraint_min, init_constraint_max, init_constraint_ratio
load siesta: solve_constraints, layout_split_horizontal, layout_split_vertical
load siesta: BlockWidget, ParagraphWidget, GaugeWidget, LineGaugeWidget, SparklineWidget, BarChartWidget, ScrollbarWidget, TreeWidget, TextAreaWidget
load siesta: ProgressWidget, TableWidget, TableColumn, TableRow, ListWidget, RadioGroupWidget, CheckboxWidget, ButtonWidget, Transition, Pulse, Slide
load siesta: BORDER_NONE, BORDER_PLAIN, BORDER_ROUNDED, BORDER_DOUBLE, BORDER_THICK, BORDER_ASCII
load siesta: ALIGN_LEFT, ALIGN_CENTER, ALIGN_RIGHT
load siesta: WRAP_NONE, WRAP_WORD, WRAP_CHAR
```

## 5. Первый проект: интерактивный счетчик с диалогом справки

Создадим полноценное интерактивное приложение с нуля.

### Шаг 1. Описание интерфейса (`src/views.spes`)

Создайте файл `src/views.spes`:

```spes
extern counter-app

// Определение цветовой темы с авто-детекцией темного/светлого режима терминала
theme mainTheme adaptive {
  bg: #1e1e2e
  fg: #cdd6f4
  primary: #89b4fa
  accent: #a6e3a1
  surface: #181825
}

// Модальный диалог справки
dialog helpDialog(title: string = "Справка") {
  modal: true
  dimBackdrop: true
  width: 52
  height: 13

  shortcuts {
    "Esc": onClose
    "q": onClose
  }

  col {
    text("Управление приложением:")
    text("  Пробел : Увеличить счетчик на 1")
    text("  r      : Сбросить счетчик в ноль")
    text("  ?      : Показать этот диалог")
    text("  Esc/q  : Закрыть справку или выйти")
    divider
    button("Понятно [Esc]")
  }
}

// Главный экран приложения
screen mainScreen {
  state {
    count: int32 = 0
  }

  shortcuts {
    "Space": onIncrement
    "r": onReset
    "?": onHelp
  }

  col(fill: true) {
    block(border: rounded, title: "Siesta Counter Demo", titleAlign: center) {
      text("Добро пожаловать в TUI на языке Yukino!")
      text("Текущее значение счетчика: ${this.count}")
      progress(value: 50, showPercentage: true)
      divider
      button("Нажми меня (Пробел)") {
        onClick: onIncrement
      }
    }
  }
}
```

### Шаг 2. Что генерирует макрос под капотом
Во время компиляции макрос `#[siesta::res]` синтезирует нативный класс Yukino. Вам не нужно писать этот код руками, но полезно понимать, как он устроен:

```yukino
public class MainScreen extends Screen {
    public count: int32
    public last_action: string
    public anim_frame: int64
    public layout_rects: Rect[]

    public fun init() {
        super("MainScreen")
        rewrite this.count = 0
        rewrite this.last_action = ""
        rewrite this.anim_frame = 0
    }

    public fun build_layout(ref ctx: LayoutContext) {
        // Вычисление flex-геометрии контейнеров col и row
    }

    public fun draw(ref buf: TerminalBuffer) {
        // Отрисовка блока, рамки, текста и прогресс-бара в буфер
    }

    public fun handle_key(key: KeyEvent) -> bool {
        // Проверка нажатия Пробела, r или ? и отправка событий
    }
}
```

### Шаг 3. Точка входа в программу (`src/main.ykn`)

В файле `src/main.ykn` инициализируем терминал, монтируем экран и запускаем цикл обработки событий:

```yukino
load std.io: terminal_size
load std.itermtool.event: poll_event, try_read_event, Event, EVENT_KEY
load std.itermtool.key: KeyEvent, KEY_CHAR, KEY_ESC, KEY_SPACE
load siesta: SiestaApp
load .views: GeneratedViews, MainScreen, HelpDialog

// Вызов макроса кодогенерации
#[siesta::res("views.spes", "locales.toml")]
class GeneratedViews {}

fun main() {
    // 1. Получаем текущие размеры окна терминала
    set sz = terminal_size()
    set app = init SiestaApp(sz.0, sz.1)

    // 2. Создаем экран и диалог
    set screen = init MainScreen()
    set help_dlg = init HelpDialog()

    // 3. Переводим терминал в сырой режим (скрываем курсор, переходим в альтернативный буфер)
    app.init_terminal()
    app.mount_screen(screen)

    // 4. Главный цикл событий в изолированном регионе памяти (защита от утечек ОЗУ)
    while region app.is_running {
        // Автоматически отслеживаем изменение размеров терминала пользователем
        app.check_resize()

        // Проверяем наличие событий ввода с таймаутом 16 мс (~60 кадров/сек)
        if poll_event(16) {
            set ev = try_read_event()
            if ev != null {
                set e = ev ?? init Event(0)
                if e.kind == EVENT_KEY && e.key != null {
                    set k = e.key ?? init KeyEvent(0, "")

                    // Если открыт модальный диалог справки
                    if app.is_dialog_open() {
                        if k.code == KEY_ESC || (k.code == KEY_CHAR && (k.char_val == "q" || k.char_val == "Q")) {
                            app.close_dialog()
                        } else {
                            help_dlg.handle_key(k)
                        }
                    } else {
                        // Обработка клавиш главного экрана
                        if k.code == KEY_ESC || (k.code == KEY_CHAR && (k.char_val == "q" || k.char_val == "Q")) {
                            break
                        } elif k.code == KEY_SPACE {
                            rewrite screen.count = screen.count + 1
                        } elif k.code == KEY_CHAR && (k.char_val == "r" || k.char_val == "R") {
                            rewrite screen.count = 0
                        } elif k.code == KEY_CHAR && k.char_val == "?" {
                            app.show_dialog(help_dlg)
                        } else {
                            screen.handle_key(k)
                        }
                    }
                }
            }
        }

        // Отрисовка кадра двойным буфером с отправкой только изменившихся ячеек
        app.render_frame()
    }

    // 5. Обязательно возвращаем терминал в исходное состояние при выходе
    app.restore_terminal()
}
```

### Шаг 4. Сборка и запуск приложения

```sh
# Сборка проекта
yukino build

# Запуск приложения
./my_app
```

При запуске откроется полноэкранный интерфейс с рамкой, индикатором выполнения и счетчиком. При нажатии на `Пробел` значение счетчика увеличивается мгновенно, без мерцания. При нажатии `?` плавно всплывает центрированный модальный диалог со скругленной рамкой и автоматическим затемнением родительского экрана под ним. При изменении размера окна консоли разметка мгновенно пересчитывается под новые габариты.
