# Язык спецификаций SPES (.spes)

Язык **SPES (`.spes`)** — это декларативный предметно-ориентированный язык (DSL) разметки пользовательских интерфейсов для библиотеки `siesta` на языке Yukino. Он спроектирован так, чтобы отделить структуру, оформление и верстку терминального интерфейса от логики приложения.

Во время компиляции проекта процедурный макрос `#[siesta::res]` парсит файлы `.spes`, валидирует граф импортов, проверяет типы и транслирует декларативную разметку в строго типизированные нативные классы Yukino (`Screen`, `Dialog`, компоненты и структуры данных), которые выполняются с предельной скоростью и нулевыми накладными расходами рантайма.

---

## 1. Структура файла и базовый синтаксис

Типовой файл спецификации `.spes` содержит заголовок модуля с уникальным идентификатором, секцию импорта зависимостей, темы оформления и декларации представлений:

```spes
// 1. Уникальный идентификатор модуля в дереве сборки
extern main-dashboard

// 2. Импорт внешних модулей по их логическим идентификаторам
use overview-screen(*)
use settings-screen(*)
use auth-forms(LoginForm, RegisterModal)

// 3. Адаптивная цветовая тема
theme catppuccinDark adaptive {
  bg: #1e1e2e
  fg: #cdd6f4
  primary: #89b4fa
  surface: #181825
}

// 4. Декларация полноэкранного представления
screen dashboardScreen {
  col(fill: true) {
    text("Центр управления Siesta") {
      fg: theme.primary
      bold: true
    }
  }
}
```

### 1.1 Директива `extern <идентификатор>`
Каждый файл спецификации обязан начинаться с директивы `extern`. Она задает общесистемный символический идентификатор файла, по которому другие файлы импортируют его содержимое.

- **Стиль именования**: компилятор принимает любые допустимые идентификаторы (`kebab-case`, `snake_case`, `camelCase`, `PascalCase`). Каноническим стилем для файлов SPES является `kebab-case` (`dashboard-views`, `auth-forms`, `network-telemetry`).
- **Сборка графа и защита от коллизий**: при компиляции макрос выполняет сканирование всех файлов `.spes` и строит реестр модулей `SpesRegistry`. Если два разных файла объявляют одинаковый идентификатор `extern`, компилятор немедленно прерывает сборку с фатальной ошибкой:
  `conflicting module identifier 'foo' defined in both 'path/a.spes' and 'path/b.spes'`.

### 1.2 Однострочные комментарии `//`
Парсер SPES поддерживает однострочные комментарии. Любой текст от двух слэшей `//` до символа конца строки полностью игнорируется:

```spes
// Это сервисный комментарий к панели метрик
row(height: 3) {
  // Выводим статус сети
  text("Сеть активна")
}
```

### 1.3 Директива `use <модуль>(...)`
Директива `use` связывает текущий файл спецификации с компонентами, экранами и диалогами из других файлов. Разрешение импорта происходит **строго по значению `extern`**, а не по имени физического файла на диске:

```spes
// Импортировать все открытые сущности из модуля telemetry-views
use telemetry-views(*)

// Выборочный импорт конкретных компонентов
use user-profiles(ProfileCard, UserAvatar)
use security-modals(ConfirmPurgeDialog)
```

- Символ `*` в круглых скобках означает импорт всех объявленных в целевом модуле экранов, диалогов и компонентов.
- Перечисление идентификаторов через запятую позволяет точно ограничить видимость нужных сущностей.

### 1.4 Локализация строк `tr(...)`
Вместо жестко закодированных строковых литералов в SPES поддерживается встроенный синтаксис интернационализации. Текст, обернутый в `tr("ключ")`, автоматически извлекается компилятором и сопоставляется с активным языковым файлом:

```spes
screen loginScreen {
  col {
    text(tr("auth.welcome_message"))
    input(placeholder: tr("auth.enter_password")) {
      password: true
    }
  }
}
```

Локализационные ключи хранятся в каталоге `locales/<язык>.json` в формате ключ-значение. Во время компиляции генерируются оптимизированные структуры словарей, а переключение языка на лету выполняется методом `app.set_locale("ru")`.

## 2. Цветовая система и оформление

Библиотека `siesta` поддерживает как стандартные 16-цветовые терминальные палитры ANSI, так и 24-битный TrueColor (16.7 миллионов цветов).

### 2.1 Поддерживаемые цветовые форматы
1. **Именованные терминальные цвета ANSI**:
   - `"default"` (стандартный цвет консоли пользователя без переопределения);
   - `"black"`, `"white"`, `"red"`, `"green"`, `"blue"`, `"cyan"`, `"yellow"`, `"magenta"`.
2. **TrueColor HEX-коды**:
   - Шестнадцатеричные строки вида `"#1e1e2e"`, `"#cdd6f4"`, `"#89b4fa"`.
   - В рантайме HEX-код преобразуется в прямые RGB ANSI-последовательности `\x1b[38;2;R;G;Bm` (для текста) и `\x1b[48;2;R;G;Bm` (для фона).

### 2.2 Объявление тем (`theme`) и адаптивность (`adaptive`)
Темы задают палитру токенов для интерфейса:

```spes
theme dracula adaptive {
  bg: #282a36
  fg: #f8f8f2
  primary: #bd93f9
  surface: #44475a
  accent: #ff79c6
}
```

- Модификатор `adaptive` указывает компилятору сгенерировать двухрежимную палитру.
- При запуске приложения на Linux и Windows рантайм вызывает функцию `detect_is_dark_mode()`, опрашивающую переменные окружения терминала (`COLORFGBG`, `TERM_THEME`, `COLOR_SCHEME`).
- Если пользователь запустил программу в светлом терминале, адаптивная тема автоматически инвертирует темные фоновые тона в контрастные светлые оттенки (`#eff1f5`), предотвращая нечитаемость черного текста на черном фоне.

### 2.3 Применение токенов темы
Любое свойство цвета у виджетов принимает ссылку на токен через префикс `theme.`:

```spes
block(title: "Мониторинг ресурсов") {
  fg: theme.primary
  bg: theme.surface
  text("Потоки активны") {
    fg: theme.accent
  }
}
```

## 3. Базовые визуальные контейнеры

В SPES существуют три основных типа верхнеуровневых визуальных блоков: `screen`, `dialog` и `component`. Каждый из них компилируется в отдельный нативный класс Yukino со строгой типизацией.

### 3.1 Экран: `screen`
Полноэкранное представление, занимающее всю видимую область терминала. Экран наследует базовый класс `Screen`:

```spes
screen overviewScreen {
  state {
    requestCount: int32 = 0
    serviceName: string = "API Gateway"
  }

  shortcuts {
    "Ctrl+R": onReload
    "q": onQuit
  }

  col(fill: true) {
    text("Служба: " + serviceName)
    button("Обновить") {
      onClick: onReload
    }
  }
}
```

#### Анатомия и жизненный цикл экрана:
1. **Наследование**: генерируемый класс объявляется как `public class OverviewScreen extends Screen`.
2. **Инициализация (`init()`)**: конструктор инициализирует базовый класс `super("OverviewScreen")`, сбрасывает счетчик анимации `anim_frame = 0`, создает пустые массивы прямоугольников компоновки и присваивает полям `state` их начальные значения.
3. **Фаза компоновки (`build_layout(ref ctx: LayoutContext)`)**: вызывается при каждом изменении размера терминала или перед перерисовкой. Рассчитывает координаты всех дочерних узлов flex-раскладки и сохраняет их в `this.layout_rects`.
4. **Фаза отрисовки (`draw(ref buf: TerminalBuffer)`)**: инкрементирует `this.anim_frame`, заливает экран базовым цветом фона темы `buf.fill(...)` и рекурсивно отрисовывает виджеты в буфер терминала с учетом активной области отсечения.
5. **Обработка клавиш (`handle_key(key: KeyEvent) -> bool`)**: последовательно сопоставляет нажатую клавишу с таблицей `shortcuts`, вызывает пользовательские методы-обработчики и возвращает `true`, если событие было обработано.

### 3.2 Модальный диалог: `dialog`
Всплывающее окно поверх активного экрана. Диалог наследует базовый класс `Dialog`:

```spes
dialog confirmDeleteDialog(itemName: string) {
  modal: true
  dimBackdrop: true
  width: 50
  height: 12

  shortcuts {
    "Esc": onCancel
    "Enter": onConfirm
  }

  col(fill: true) {
    text("Удаление объекта") {
      bold: true
      fg: "red"
    }
    paragraph("Вы действительно хотите удалить " + itemName + "? Действие необратимо.")
    row {
      button("Отмена") { onClick: onCancel }
      button("Удалить") { onClick: onConfirm }
    }
  }
}
```

#### Параметры и поведение диалога:
- `modal: true`: захватывает фокус ввода. События клавиатуры и мыши изолируются внутри диалога и не просачиваются к экрану под ним.
- `dimBackdrop: true`: рантайм автоматически затемняет фоновый экран. Все символы терминала вне прямоугольника диалога помечаются атрибутом `dim = true`.
- `width` и `height`: фиксированные геометрические размеры окна в символьных ячейках.
- **Автоматическое центрирование**: рантайм вычисляет смещение `dx = (term_w - size_w) / 2` и `dy = (term_h - size_h) / 2` и рисует аккуратную двойную рамку `╭───╮` вокруг окна.

### 3.3 Переиспользуемый компонент: `component`
Автономный визуальный элемент, который можно параметризовать и встраивать в экраны и диалоги:

```spes
component userCard(name: string, role: string, isActive: bool = true) {
  block(border: rounded) {
    row {
      text(name) { bold: true }
      text(if isActive { " [В сети]" } else { " [Офлайн]" }) {
        fg: if isActive { "green" } else { "white" }
      }
    }
    text("Должность: " + role) { dim: true }
  }
}
```

- Параметры в круглых скобках становятся полями и аргументами конструктора `init(...)`.
- Компонент компилируется в самостоятельный класс с собственными методами `build_layout` и `draw`.
- Компоненты могут принимать локальное состояние через блок `state`.

## 4. Состояние (`state`) и двусторонняя привязка (`bind:`)

В блоке `state` объявляются реактивные переменные представления с явными типами и начальными значениями:

```spes
screen accountSettingsScreen {
  state {
    email: string = "user@domain.org"
    subscribeNewsletter: bool = true
    preferredServer: int32 = 0
  }

  col {
    text("Настройки учетной записи")
    
    // Двусторонняя привязка строки к полю ввода
    input(placeholder: "Введите адрес почты") {
      bind: email
    }

    // Привязка логического значения к флажку
    checkbox("Получать сводку новостей") {
      bind: subscribeNewsletter
    }

    // Привязка индекса к группе радиокнопок
    radiogroup(vertical: true) {
      bind: preferredServer
    }
  }
}
```

### Механика работы двусторонней привязки:
1. Во время компиляции макрос создает в классе экрана геттеры и сеттеры для каждого связанного поля: `get_email() -> string`, `set_email(v: string)`.
2. При отрисовке виджет получает актуальное значение из соответствующего поля экрана.
3. При вводе пользователем текста в виджет `InputWidget` или нажатии пробела на `CheckboxWidget`, внутренний обработчик событий автоматически обновляет поле состояния `this.email` или `this.subscribeNewsletter`.
4. Разработчику не требуется писать рутинный код чтения строковых буферов из UI-дерева.

## 5. Таблица клавиатурных сокращений (`shortcuts`)

Блок `shortcuts` позволяет объявлять обработку горячих клавиш:

```spes
shortcuts {
  "Ctrl+S": onSave
  "Ctrl+Q": onQuit
  "F5":     onRefresh
  "Tab":    onFocusNext
  "Esc":    onDismiss
  "Enter":  onSubmit
  "Space":  onToggle
  "Up":     onPrevious
  "Down":   onNext
}
```

Макрос транслирует эту таблицу в строго типизированный метод:
```yukino
public fun handle_key(key: KeyEvent) -> bool {
    if key.ctrl && key.char_val == "s" {
        this.trigger_onSave()
        rewrite this.last_action = "onSave"
        return true
    }
    if key.code == KEY_ESC {
        this.trigger_onDismiss()
        rewrite this.last_action = "onDismiss"
        return true
    }
    return false
}
```

## 6. Декларативная блочная Flex-раскладка

`siesta` использует интуитивную модель блочной flex-раскладки, основанную на контейнерах `col` (вертикальная колонка) и `row` (горизонтальная строка).

```spes
col(fill: true) {
  // Верхняя навигационная панель фиксированной высоты
  row(height: 3) {
    text("Логотип")
    text("Пользователь: admin")
  }

  // Центральная область, разделенная на боковое меню и рабочий холст
  row(fill: true, gap: 1) {
    col(width: 25) {
      text("Боковое меню")
    }
    col(fill: true) {
      text("Основной контент")
    }
  }

  // Нижний подвал фиксированной высоты
  row(height: 1) {
    text("Статус: Подключено")
  }
}
```

### Свойства контейнеров `col` и `row`:
- `fill: true`: элемент жадно занимает всё оставшееся пространство родительского контейнера (аналог `flex-grow: 1`). Если несколько элементов имеют `fill: true`, пространство делится между ними поровну.
- `width` / `height`: фиксированный размер в символьных знакоместах.
- Процентные размеры: строковые значения `width: "50%"`, `height: "20%"`.
- `padding`, `paddingX`, `paddingY`: внутренние отступы от границ контейнера в ячейках.
- `gap`: расстояние между соседними дочерними элементами в ячейках.
- `justify`: выравнивание по главной оси (`start`, `center`, `end`).
- `align`: выравнивание по поперечной оси (`stretch`, `start`, `center`, `end`).

### Вспомогательные элементы: `divider` и `spacer`
- `divider`: горизонтальная разделительная линия, автоматически заполняющая доступную ширину символом `─`.
- `spacer`: пружинный элемент с `fill: true`, сдвигающий следующие за ним элементы к правому или нижнему краю контейнера.

## 7. Адаптивность и диапазоны экрана (Breakpoints)

На терминалах различных размеров (от узкого встроенного окна на 60 колонок до широкоформатного полноэкранного эмулятора) интерфейс должен корректно адаптироваться. В SPES предусмотрена декларативная система адаптивности:

```spes
col(fill: true) {
  // Панель бокового дерева скрывается на экранах уже 90 символов
  tree(minWidth: 90)

  // Микрографик скрывается на компактных дисплеях
  sparkline(hideBelow: 75)

  // Блок детальной аналитики отображается только в профиле desktop
  block(breakpoint: "desktop") {
    text("Расширенная аналитика")
  }
}
```

### Доступные правила видимости:
- `minWidth` / `min_w`: минимальная ширина экрана в колонках, при которой элемент рисуется.
- `minHeight` / `min_h`: минимальная высота экрана в строках.
- `maxWidth` / `max_w`: максимальная ширина экрана для отображения элемента.
- `maxHeight` / `max_h`: максимальная высота экрана.
- `hideBelow`: синоним `minWidth`.
- `breakpoint`: строковый идентификатор категории терминала:
  - `"desktop"`: ширина $\ge 120$ символов.
  - `"compact+"`: ширина $\ge 80$ символов.
  - `"compact"`: ширина от $80$ до $119$ символов.
  - `"mobile"`: ширина $< 80$ символов.

## 8. Декларативные анимации (`anim:`)

Для выделения статусов, предупреждений и динамических списков SPES предоставляет декларативное свойство `anim:`:

```spes
col {
  text("Синхронизация с сервером...") {
    anim: pulse
    fg: "yellow"
  }

  progress(value: 80) {
    anim: slide
    fg: "cyan"
  }
}
```

### Поддерживаемые директивы анимации:
1. `anim: pulse`: активирует циклическое мерцание акцента. В коде генератора вычисляется условие `(this.anim_frame % 20 < 10)`, динамически переключающее атрибут `bold`.
2. `anim: slide`: горизонтальное циклическое смещение координат на основе выражения `+ cast(this.anim_frame % 8, "int32")`.
3. **Интеграция с циклом кадров**: экран автоматически инкрементирует счетчик `this.anim_frame` при каждом вызове метода `draw(...)`. Анимация не требует создания фоновых потоков или таймеров, сохраняя детерминированность терминального вывода.

## 9. Полная спецификация всех 18 виджетов

Каждый виджет библиотеки `siesta` обладает строгой спецификацией, параметрами в `.spes` и соответствующим классом рантайма в пространстве `core.widgets`.

---

### 9.1 `text`
Однострочный текст с форматированием стилей и поддержкой UTF-8.

- **Класс рантайма**: `TextWidget` (`libs/core/core/widgets/text.ykn`).
- **Назначение**: вывод статичных заголовков, меток, строковых значений и вычисляемых выражений.
- **Свойства SPES**:
  - Первый аргумент: строка текста (например, `"Привет"`, `tr("key")` или переменная состояния).
  - `fg`: цвет текста (`"default"`, `"cyan"`, `"#cdd6f4"`).
  - `bg`: цвет фона (`"default"`, `"#1e1e2e"`).
  - `bold: bool`: полужирное начертание текста.
  - `dim: bool`: приглушенная яркость (тусклый цвет).
  - `italic: bool`: курсивное начертание.
  - `underline: bool`: подчеркивание текста.
  - `reverse: bool`: инверсия цветов текста и фона.
  - `anim`: директива анимации (`pulse`, `slide`).
- **Пример**:
  ```spes
  text("Сервер запущен на порту 8080") {
    fg: "green"
    bold: true
  }
  ```

---

### 9.2 `block`
Структурный блок-контейнер с декоративной рамкой, заголовком и внутренними отступами.

- **Класс рантайма**: `BlockWidget` (`libs/core/core/widgets/block.ykn`).
- **Назначение**: группировка связанных элементов, создание карточек, секций и панелей.
- **Свойства SPES**:
  - `border`: стиль рамки (`rounded`, `plain`, `double`, `thick`, `ascii`, `none`).
    - `rounded`: скругленные углы `╭ ╮ ╰ ╯`.
    - `plain`: одинарные тонкие линии `┌ ┐ └ ┘`.
    - `double`: двойные линии `╔ ╗ ╚ ╝`.
    - `thick`: жирные линии `┏ ┓ ┗ ┛`.
    - `ascii`: совместимый набор символов `+ - | +`.
    - `none`: без отрисовки контура рамки.
  - `title: string`: текстовый заголовок, врезанный в верхнюю границу рамки.
  - `titleAlign`: выравнивание заголовка (`left`, `center`, `right`).
  - `fg`, `bg`: цвета рамки и фона внутреннего пространства.
  - `padding`: внутренний отступ от рамки до содержимого.
- **Пример**:
  ```spes
  block(border: rounded, title: "Параметры кластера", titleAlign: center) {
    fg: "cyan"
    text("Узлов активно: 12")
  }
  ```

### 9.3 `paragraph`
Многострочный текстовый блок с автоматическим переносом строк и выравниванием.

- **Класс рантайма**: `ParagraphWidget` (`libs/core/core/widgets/paragraph.ykn`).
- **Назначение**: вывод длинных описаний, справочных статей, лицензий и сообщений об ошибках.
- **Свойства SPES**:
  - Первый аргумент: строковый текст.
  - `wrap`: режим переноса строк:
    - `word`: корректный перенос по границам слов без разрыва лексем.
    - `char`: перенос строго по границе ширины контейнера.
    - `none`: обрезка строк без переноса.
  - `align`: горизонтальное выравнивание строк (`left`, `center`, `right`).
  - `fg`, `bg`: цвета текста и фона.
- **Пример**:
  ```spes
  paragraph("Язык Yukino компилируется в эффективный нативный бинарный код без сборщика мусора.") {
    wrap: word
    align: left
    fg: "white"
  }
  ```

### 9.4 `button`
Интерактивный элемент действия со стилизацией ролей и состояний фокуса.

- **Класс рантайма**: `ButtonWidget` (`libs/core/core/widgets/button.ykn`).
- **Назначение**: запуск команд, подтверждение форм, навигация.
- **Свойства SPES**:
  - Первый аргумент: текст надписи на кнопке.
  - `role`: семантическая роль оформления:
    - `default`: нейтральная рамка `[ Текст ]`.
    - `primary`: акцентная кнопка основного действия (синий/бирюзовый цвет).
    - `success`: положительное подтверждение (зеленый цвет).
    - `warning`: предупреждение (желтый цвет).
    - `danger`: деструктивное действие (красный цвет).
  - `onClick`: имя метода-обработчика нажатия на кнопку.
  - `disabled: bool`: отключенное неактивное состояние.
  - `fg`, `bg`: переопределение базовых цветов кнопки.
- **Пример**:
  ```spes
  button("Применить изменения", role: primary) {
    onClick: onApplySettings
  }
  ```

  - `fg`, `bg`: цвета текста и фона поля ввода.

### 9.11 `progress`

- **Назначение**: визуализация завершения загрузки файлов, сборки, длительных операций.
- **Механика субпикселей**: функция `fractional_block` использует 8 символов дробных долей Unicode (`▏`, `▎`, `▍`, `▌`, `▋`, `▊`, `▉`, `█`), обеспечивая плавный индикатор даже при малой ширине в 10 символов.
- **Свойства SPES**:

### 9.18 `canvas`
Холст векторной и растровой графики высокой четкости на базе шрифта Брайля.

- **Класс рантайма**: `CanvasWidget` (`libs/core/core/widgets/canvas.ykn`).
- **Назначение**: отрисовка произвольных геометрических линий, графиков функций, многоугольников и схем.
- **Разрешение Брайля**: каждая символьная ячейка терминала содержит матрицу 2 точки по горизонтали на 4 точки по вертикали ($2 \times 4$). Терминальное окно $80 \times 24$ ячейки превращается в графический холст с разрешением $160 \times 96$ пикселей.
- **Свойства SPES**:
  - `width: int32`: ширина холста в ячейках терминала.
  - `height: int32`: высота холста в ячейках терминала.
  - `fg`, `bg`: цвета отрисовки пикселей холста.
- **Пример**:
  ```spes
  canvas(width: 60, height: 12) {
    fg: "green"
  }
  ```

## 10. Комплексный практический пример: Дашборд мониторинга

Ниже приведен полный пример файла спецификации `dashboard.spes`, объединяющий модульность, темы, адаптивность, анимацию и компоненты:

```spes
extern cloud-monitor

use auth-forms(UserBadge)

theme oceanicDark adaptive {
  bg: #1b2b34
  fg: #d8dee9
  primary: #6699cc
  surface: #101a20
  accent: #99c794
}

component metricTile(caption: string, value: string, isOk: bool = true) {
  block(border: rounded) {
    text(caption) { dim: true }
    text(value) {
      bold: true
      fg: if isOk { theme.accent } else { "red" }
    }
  }
}

screen monitorScreen {
  state {
    activeTab: int32 = 0
    searchQuery: string = ""
    isLiveUpdate: bool = true
  }

  shortcuts {
    "Ctrl+Q": onQuit
    "Ctrl+R": onRefresh
    "F1": onShowHelp
  }

  col(fill: true) {
    // Верхняя шапка
    row(height: 3) {
      text("Cloud Infrastructure Monitor") {
        bold: true
        fg: theme.primary
      }
      spacer
      text("Статус: Активен") {
        anim: pulse
        fg: theme.accent
      }
    }

    divider

    // Панель карточек метрик
    row(height: 5, gap: 1) {
      metricTile("Загрузка CPU", "24.5%", true)
      metricTile("Очередь сообщений", "1,420", true)
      metricTile("Ошибок HTTP", "0.02%", true)
    }

    // Рабочая область
    row(fill: true, gap: 1) {
      // Боковая колонка поиска
      col(width: 30) {
        text("Фильтр сервисов:")
        input(placeholder: "Имя пода...") {
          bind: searchQuery
        }
        checkbox("Автообновление (1 сек)", checked: true) {
          bind: isLiveUpdate
        }
      }

      // Основной холст со списком и графиком
      col(fill: true) {
        tabs(activeIndex: 0)
        table(id: clusterTable) {
          width: "100%"
          height: 10
        }
      }
    }

    // Нижняя статусная строка
    row(height: 1) {
      text("Готово | F1 Помощь | Ctrl+Q Выход") { dim: true }
    }
  }
}
```
